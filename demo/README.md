# demo/ — generated build artifact

This directory is regenerated by `.github/workflows/pages.yml` on every push to
`main`; `index.html`, `css/`, `js/` and `themecfg/` here are copies of the theme
source at the repo root and must not be edited by hand — change the source
instead, and CI will reproduce this directory.

The duplication is intentional: GitHub Pages can only serve files under its own
deployment root, so `demo/` is the shallow, self-contained copy that gets
published. The workflow is the single source of truth for that copy, which is
what keeps it from drifting.

`demo/data/` and `demo/static/` are the exception: they are demo *content*
(a small blog fixture), not build output, so the workflow leaves them untouched
and they are edited normally.
